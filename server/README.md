# ESP32 audio receiver

This small Python service accepts mono 16 kHz signed PCM16 little-endian audio
over a WebSocket and saves completed sessions as WAV files. It receives audio
only; speech recognition is not integrated yet.

## Run locally

From the repository root, install dependencies and start the service:

```powershell
py -m pip install -r server/requirements.txt
py -m uvicorn server.app:app --host 0.0.0.0 --port 8000
```

The health endpoint is `http://<server-host>:8000/health`. The audio endpoint
is `ws://<server-host>:8000/ws/audio`.

On the ESP32's Wi-Fi network, use the computer's LAN IP address for
`<server-host>` (not `localhost`). Allow inbound TCP port 8000 through the
computer's firewall. Do not expose this unauthenticated development receiver
directly to the public internet.

Completed WAV files are written to `recordings/` under the server's working
directory. Set `AUDIO_RECORDINGS_DIR` to choose another location.

## WebSocket protocol

1. Send a JSON text message:

   ```json
   {"type":"start","session_id":"optional-client-id","audio":{"sample_rate":16000,"channels":1,"format":"pcm_s16le"}}
   ```

2. Wait for `start_ack`. The returned `session_id` is generated by the server.
3. Send audio as binary WebSocket messages containing raw PCM16LE bytes. Each
   message must contain whole 16-bit samples.
4. Send `{"type":"end","reason":"vad_silence"}` as JSON text.
5. Receive a `result` message with the saved WAV filename, byte count, and
   duration.

The receiver accepts up to 120 seconds per connection. TCP/WebSocket provides
reliable ordered delivery, so chunks do not need application-level sequence
numbers. A disconnected or invalid/incomplete transfer is discarded.

## Limitations

- No ASR/transcription, authentication, TLS, or device identity is implemented.
- The current firmware does not yet join Wi-Fi or connect to this endpoint; the
  endpoint defines the server side of the handoff protocol.
- For remote deployment, put the service behind an authenticated TLS reverse
  proxy and use `wss://` from the device.
